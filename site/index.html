What the patterns say

Patterns

  1. Auth: OAuth2 dominates (66 apps), and half the apps (50) also offer an API key (84 accept an API key or bearer token) for single-user use, so toolkits should support both.
  2. Self-serve vs gated: Communications, Developer/Infra and Productivity are fully self-serve (10 of 10 each). Marketing/Ads, Ecommerce and Finance are the most gated (4 of 10 each).
  3. Most common blocker: credential gates such as paid plans or trials (19 apps), then admin or partner approval (9).
  4. MCP is going mainstream: the agent found an official MCP server for 53 vendors, and the hand check showed it still under-counts recent launches.
  5. Composio already covers 75 of 100. The 7 easy wins are ready-now apps not yet on Composio: Vonage, systeme.io, WooCommerce, Magento (Adobe Commerce), MongoDB Atlas, Binance, Reducto.
  6. Needs outreach (11): DealCloud, Gladly, LinkedIn Ads, Salesforce Commerce Cloud, fanbasis, Sherlock, Waterfall.io, Paygent Connect, PitchBook, Otter AI, Consensus. These go through partnerships, not engineering.

What the agent got wrong (from the 20-app hand check)

  1. Gating and auth lists were the weakest fields (most misses were in auth_methods and credential_access): trials vs paid plans vs app review are buried in pricing pages.
  2. It labelled documented REST APIs as SDK/CLI-only (Twilio and Snowflake in pass 1; Close, Vercel, Asana and Snowflake from the auditor).
  3. It missed recently launched official MCP servers (Twilio, Airtable, Snowflake, systeme.io, iPayX).
  4. The independent auditor prompt scored 69% vs 62% for the first pass. The automatic fact-check did not move accuracy, because its flags (auth word not on the page) did not target the real errors. Next step: gating-specific checks and source-quote verification.

How it works

A Python pipeline. Every number on this page is computed from its output, none typed by hand.

  1. ResearchGemini reads each vendor's official docs and fills a fixed schema with evidence URLs. One JSON per app.
  2. Auto-verifyRules check logic and schema, open every evidence link, and flag weak answers. 47 apps flagged.
  3. Fact-checkA second prompt re-researches only flagged apps. 6 records changed.
  4. Composio lookupThe Composio SDK lists existing toolkits: 75 of 100 already covered.
  5. Human audit20 apps, 2 per category, re-researched blind and then checked by me against official docs.
  6. PublishAnalysis script computes the patterns and builds this page plus CSV, JSON and llms.txt.

Where a human was needed

  • Defining the vocabulary: what counts as self-serve, gated and buildable.
  • Hand-checking the 20-app audit sample. This is the ground truth for accuracy.
  • Confirming fuzzy name matches against Composio's toolkit list.
  • Writing the pattern summary from the computed numbers.

Where it fell short

8 apps the agent could not settle (credentials, blocker or MCP left "unclear"): Intercom, Plain, Pinterest, fanbasis, Netlify, NotebookLM, Otter AI, Consensus. Public docs don't say; these need a human or a vendor conversation.

1 apps without a result: Grain.

  • Accuracy is measured on a 20-app sample, not all 100. The rest rely on the automatic loop. The sample is stratified and random (2 per category), not a separate held-out split: prompts were not tuned on it, but it is the only test set.
  • The human labels started from the blind auditor's answers, so there is some anchoring risk. 18 of 20 rows were corrected, each with a note.
  • Gemini Google Search was unavailable on the free key, so the agent read vendor docs via URL context. Pages that block bots or need JavaScript count as "unverifiable", not confirmed, and the model may fill gaps from memory.
  • Gating is one column. Sandbox vs production access and extra requirements (developer tokens, app review, business verification) are not split out, so gating is the least reliable field.
  • MCP is official yes/no; community MCP servers appear only in notes. Composio coverage is a separate cross-check from Composio's catalog and was never fed to the research agent.
  • Temperature 0.2 on an overloaded model, so reruns can differ slightly.
  • Low-confidence answers left unreviewed: none.
  • Results reflect the docs on 24 Nov 2026; APIs and pricing change.
